# Task 3 policy drift diagnostic (issue #177)

## Question and protocol

The audit asks whether Task 3 training changed action values specifically in
states containing public opponents. It uses each #175 checkpoint's own replay,
with the initial network as the pre-training reference. For each replay, the
same 512 evenly spaced transition indices are used for all comparisons. Legal
action masks are applied before greedy action selection. The audit records
online-network Q drift, target-network Bellman TD errors, action-ranking changes,
reward distribution, checkpoint hashes, and sample indices. It is read-only,
serial, CPU-only, and bounded by five minutes, 1 GiB RAM, and one worker thread.

The diagnostic was registered in issue #177 before execution. The retained input
archive is the #175 evidence release:
<https://github.com/1BlauNitrox/mle-final-project/releases/tag/issue175-evidence-v1>.

## Observed result

The observations show substantial online Q/action drift on opponent-present
states while opponent-absent states remain unchanged in the sampled
transitions. Across the ten models, opponent-present greedy-action changes are
25.8--47.1%. Mean absolute Bellman TD error fell in 9 of 10 models (initial
range 0.627--0.861; final range 0.599--0.746), but signed TD-error directions
were not consistent: sign changes were 27.9--39.8% per model. These are
post-hoc replay diagnostics, not a hunting performance comparison.

The exact per-model values, Q shifts, action counts, TD-error summaries, sample
indices, and checkpoint hashes are retained in `observations.json`.

This is evidence of opponent-conditioned representation use, not evidence that
hunting improved. Because each model contributes its own replay population, the
audit cannot estimate a treatment effect or establish causality. The directional
TD-error summary was generated by the analyzer in this PR.

## Reproduction

```text
python -m scripts.audit_task3_policy_drift --root PATH_TO_ISSUE175_EVIDENCE --output new-diagnostic.json
```

The output is lossless for the bounded sample: it includes per-model sample
indices, hashes, Q/action summaries, TD-error sign counts, and resource usage.

## Decision and limitations

This diagnostic does not select a checkpoint and does not close #177. It
supports the separately registered controlled follow-ups #178 and #179.
